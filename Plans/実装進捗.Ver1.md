  - メッシュのデータ形式: `positions` / `normals` / `uvs` を `Float32Array`、`indices` を `Uint32Array`(1チャンクの最大面数がUint16の範囲を超えうるため)とし、1面は4頂点・2三角形・頂点順序は表側から見て反時計回り(CCW)。
  - チャンク境界(隣接チャンク未取得)に接する面は、隣接ブロックが不明なため外周面として描画対象に含める。
  - Web Workerの入出力契約: 入力 `{ blocks: Uint8Array }`、出力は `positions` / `normals` / `uvs` / `indices` の4つの `Transferable` な `ArrayBuffer`。
  - テクスチャアトラス: 画像・グリッド仕様が未定のため、本ステップでは各面に単位UV座標((0,0),(1,0),(1,1),(0,1))を割り当てるロジックのみとし、ブロックID別のアトラスオフセット算出・実アトラス画像・Babylon.jsへの投入と描画は後続ステップへ委ねる(`Plans/ゲーム実装計画.Ver1.md` ステップ3の作業項目も同様に更新)。
- 実施内容:
  - [wwwroot/js/world/ChunkMeshBuilder.ts](../Sources/Shos.Minecraft/wwwroot/js/world/ChunkMeshBuilder.ts) を新規追加。ステップ2の `Chunk` / `BlockTypes` の公開インターフェースと座標計算を変更せず、`buildChunkMesh(chunk)` で不可視面カリングとメッシュデータ(`positions`/`normals`/`uvs`/`indices`)を生成する。不透明判定は、現在のブロック定義で非衝突集合(空気・水)がそのまま非不透明集合と一致するため `BlockTypes.isCollidable` を用いた(コード内にその旨のコメントを記載)。
  - [wwwroot/js/world/ChunkMeshWorker.ts](../Sources/Shos.Minecraft/wwwroot/js/world/ChunkMeshWorker.ts) を新規追加。`ChunkMeshBuilder` を用いてWeb Worker上でメッシュを生成し、結果を `Transferable` な `ArrayBuffer` としてメインスレッドへ返す(詳細システム設計書 2.2 の必須要件)。ブラウザの Dedicated Worker としてのみ動作するため、Node実行・自動テストの対象外とした。
  - 両ファイルとも既存の `.ts` と同様、ビルドツールなしで `Microsoft.TypeScript.MSBuild` によりコンパイルされる構成を維持。画面への読み込み(Worker起動・メッシュのBabylon.jsへの投入)は、描画統合を担う後続ステップで行うため、本ステップでは `Views/` の変更は行っていない。

  - `dotnet build Sources\Shos.Minecraft.slnx` 成功(`ChunkMeshWorker.ts` の `.buffer` プロパティの型を `ArrayBufferLike` に修正後)。
