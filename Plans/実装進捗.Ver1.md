## ステップ2: ブロックとチャンクの基盤 — 完了

- 実施内容:
  - [wwwroot/js/world/BlockTypes.js](../Sources/Shos.Minecraft/wwwroot/js/world/BlockTypes.js) を新規追加。詳細システム設計書 第2章 2.1 のブロックID対応表(ID 0〜10、`isCollidable` / `isBreakable` / `requiredTool` / `breakTimeSeconds` / `dropBlockId`)をそのまま実装し、`getBlockType` / `isCollidable` / `isBreakable` を公開。
  - [wwwroot/js/world/Chunk.js](../Sources/Shos.Minecraft/wwwroot/js/world/Chunk.js) を新規追加。`Uint8Array`(長さ 16×256×16)でブロックIDを保持し、`getIndex(x, y, z) = x + z * 16 + y * 16 * 16` を実装。`getBlockId` / `setBlockId` で読み書きし、`isCollidableAt` で `BlockTypes` の非衝突判定(空気・水)に委譲。範囲外座標は `RangeError` を送出。
  - 両ファイルは UMD 形式(ブラウザの `<script>` 読み込みと Node の `require` の両方に対応)とし、既存の `wwwroot/js/game.js` と同様にビルドツールなしで動作する構成を維持。画面への読み込み(`<script>` タグ追加)はステップ3(描画・メッシュ生成)以降で行うため、本ステップでは `Views/` の変更は行っていない。
  - 既存の `.NET` テスト基盤には JS 実行機能がないため、[Shos.Minecraft.Tests/js-verification/ChunkSmokeTest.js](../Sources/Shos.Minecraft.Tests/js-verification/ChunkSmokeTest.js) を新規追加し、Node の標準 `assert` のみで検証する再現可能なスクリプトとした(この JS ファイルは `.csproj` のビルド対象には含まれない)。
- 動作確認結果:
  - `node Sources\Shos.Minecraft.Tests\js-verification\ChunkSmokeTest.js` を実行し、以下をすべて確認: 座標計算式の一致、指定座標に設定した値を同じ値で読み出せること、未設定座標が既定値(空気, ID:0)であること、空気(ID:0)・水(ID:8)が非衝突、土(ID:1)が衝突として判定されること、範囲外座標で `RangeError` が送出されること。出力: `ChunkSmokeTest: すべての検証に成功しました。`
  - `dotnet build Sources\Shos.Minecraft.slnx` 成功。
  - `dotnet test Sources\Shos.Minecraft.slnx` 成功(既存2件、回帰なし)。
- 未解決事項: なし。ブロックの描画・メッシュ生成(不可視面カリング)はステップ3で対応予定。
