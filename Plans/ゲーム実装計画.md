## 第1章:実装方針

- 本計画は、1つのステップを「実装 → 動作確認 → 次のステップへ着手」の順で完了させてから次のステップに進めるステップバイステップ方式とする。複数のステップを並行して着手することはしない。これにより、問題が発生した際にどのステップに原因があるかを常に切り分けられる状態を保つ。
- 各ステップの完了時点で、成果物(クライアント/サーバー)は単独でビルド・起動できる状態を保つ。あるステップの成果物が次のステップの未実装部分に依存してビルドできなくなることは許容しない。
- ステップの出発点は `詳細システム設計書.md` 第6章「開発ロードマップ」記載の Step 1〜Step 6 とし、それぞれを実装・検証可能な単位にさらに分割する。

## 第3章:各ステップの詳細

### ステップ0: 補助作業: 開発環境構築
- 作業項目:
  - `Sources/Client/package.json`(TypeScript + Babylon.js の依存関係とビルドスクリプト)
  - `Sources/Client/tsconfig.json`
  - `Sources/Client/src/main.ts`(Babylon.jsの空シーンを起動するエントリーポイント)
  - `Sources/Server/Shos.Minecraft.Server.csproj`(ASP.NET Core Web APIプロジェクト)
  - `Sources/Server/Program.cs`(最小限のWeb APIホスト起動処理)
- 完了条件: クライアントのビルドコマンド実行後、ブラウザで空のBabylon.jsシーン(背景色のみ)が表示できることを目視で確認できる。サーバーのビルド・起動コマンド実行後、疎通確認用のエンドポイントにHTTPリクエストを送信し200応答をログで確認できる。
- 依存関係: なし。

### ステップ1: ブロック種別データ定義
- 作業項目:
  - `Sources/Client/src/world/BlockTypes.ts`(`IBlockType` インターフェースとID0〜10のブロック定義配列)
- 完了条件: 単体テストまたはコンソール出力で、ID3(石)の `requiredTool` が `"woodenPickaxe"`、ID8(水)の `isCollidable` が `false` であることをログで確認できる。
- 依存関係: ステップ0の完了が前提。

### ステップ2: チャンクデータ構造実装
- 作業項目:
  - `Sources/Client/src/world/Chunk.ts`(`IChunk` 実装、`Uint8Array` 長さ16×256×16の生成、`index = x + z * 16 + y * 16 * 16` によるアクセサ関数)
  - `Sources/Client/src/world/VoxelWorld.ts`(`IVoxelWorld` 実装、チャンクを `Map` で管理)
- 完了条件: 座標(1,2,3)にブロックIDを設定した後、同座標を読み出すと同じ値が返ることをコンソール出力で確認できる。
