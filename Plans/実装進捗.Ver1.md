## ステップ2: ブロックとチャンクの基盤 — 完了

- 実施内容:
  - [wwwroot/js/world/BlockTypes.js](../Sources/Shos.Minecraft/wwwroot/js/world/BlockTypes.js) を新規追加。詳細システム設計書 第2章 2.1 のブロックID対応表(ID 0〜10、`isCollidable` / `isBreakable` / `requiredTool` / `breakTimeSeconds` / `dropBlockId`)をそのまま実装し、`getBlockType` / `isCollidable` / `isBreakable` を公開。
  - [wwwroot/js/world/Chunk.js](../Sources/Shos.Minecraft/wwwroot/js/world/Chunk.js) を新規追加。`Uint8Array`(長さ 16×256×16)でブロックIDを保持し、`getIndex(x, y, z) = x + z * 16 + y * 16 * 16` を実装。`getBlockId` / `setBlockId` で読み書きし、`isCollidableAt` で `BlockTypes` の非衝突判定(空気・水)に委譲。範囲外座標は `RangeError` を送出。
  - 両ファイルは UMD 形式(ブラウザの `<script>` 読み込みと Node の `require` の両方に対応)とし、既存の `wwwroot/js/game.js` と同様にビルドツールなしで動作する構成を維持。画面への読み込み(`<script>` タグ追加)はステップ3(描画・メッシュ生成)以降で行うため、本ステップでは `Views/` の変更は行っていない。
  - 既存の `.NET` テスト基盤には JS 実行機能がないため、[Shos.Minecraft.Tests/js-verification/ChunkSmokeTest.js](../Sources/Shos.Minecraft.Tests/js-verification/ChunkSmokeTest.js) を新規追加し、Node の標準 `assert` のみで検証する再現可能なスクリプトとした(この JS ファイルは `.csproj` のビルド対象には含まれない)。
- 動作確認結果:
  - `node Sources\Shos.Minecraft.Tests\js-verification\ChunkSmokeTest.js` を実行し、以下をすべて確認: 座標計算式の一致、指定座標に設定した値を同じ値で読み出せること、未設定座標が既定値(空気, ID:0)であること、空気(ID:0)・水(ID:8)が非衝突、土(ID:1)が衝突として判定されること、範囲外座標で `RangeError` が送出されること。出力: `ChunkSmokeTest: すべての検証に成功しました。`
  - `dotnet build Sources\Shos.Minecraft.slnx` 成功。
  - `dotnet test Sources\Shos.Minecraft.slnx` 成功(既存2件、回帰なし)。
- 未解決事項: なし。ブロックの描画・メッシュ生成(不可視面カリング)はステップ3で対応予定。

## 設計変更: フロントエンド実装言語をTypeScriptへ統一

`Specifications/詳細システム設計書.Ver1.md` 第2章に「2.0 実装言語とビルド」を新設し、フロントエンドの実装言語を **TypeScript**(`.ts`)に統一する規定を追記した。これに伴い、既存の `.js` 手書き実装(ステップ1・2)を `.ts` へ全面的に書き直した。

- ビルド方式: `Microsoft.TypeScript.MSBuild`(NuGet, v7.0.0)を [Shos.Minecraft.csproj](../Sources/Shos.Minecraft/Shos.Minecraft.csproj) に追加し、`dotnet build` 時に `.ts` を自動で `.js` へコンパイルする構成とした(Node.js/npmのビルドツールチェーンは導入しない)。
- [tsconfig.json](../Sources/Shos.Minecraft/tsconfig.json) を新規追加(`target: ES2020`、`lib: ["ES2020", "DOM"]`、`strict: true`、`include: wwwroot/js/**/*.ts`)。ソースマップの出力(`.js.map`)はNuGetパッケージの既定動作に従う(tsconfig側での明示的な無効化はビルドに反映されないため指定していない)。
- [wwwroot/js/global.d.ts](../Sources/Shos.Minecraft/wwwroot/js/global.d.ts) を新規追加。UMDパターンでNode(検証スクリプト)とブラウザの両方から読み込むための `module` / `require` の最小限のアンビエント宣言を定義。
- 書き直したファイル(いずれも `.js` は削除し `.ts` に置換。コンパイル後の `.js` は `wwwroot/js` 配下に同居する):
  - [wwwroot/js/game.ts](../Sources/Shos.Minecraft/wwwroot/js/game.ts)(旧 `game.js`)
  - [wwwroot/js/world/BlockTypes.ts](../Sources/Shos.Minecraft/wwwroot/js/world/BlockTypes.ts)(旧 `BlockTypes.js`。`IBlockType` / `IBlockTypesModule` インターフェースを追加し型を明示)
  - [wwwroot/js/world/Chunk.ts](../Sources/Shos.Minecraft/wwwroot/js/world/Chunk.ts)(旧 `Chunk.js`。プロトタイプ関数からTypeScriptの `class Chunk` へ書き換え、`IChunk` / `IChunkStatic` インターフェースを追加)
  - [Plans/ゲーム実装計画.Ver1.md](ゲーム実装計画.Ver1.md) のステップ1・ステップ2・第4章リスク欄の `.js` ファイル名表記を `.ts` に更新。
- 動作確認結果:
  - `dotnet build Sources\Shos.Minecraft.slnx` 成功(`.ts` → `.js` のコンパイルを含む)。生成された `.js` に `class Chunk` 等のES2020構文が保持されていることを確認(tsconfigの `target: ES2020` が反映されている)。
  - `node Sources\Shos.Minecraft.Tests\js-verification\ChunkSmokeTest.js` を再実行し、コンパイル後の `.js` に対する全検証が成功することを確認。
  - `dotnet test Sources\Shos.Minecraft.slnx` 成功(既存2件、回帰なし)。
  - ビルド後に `wwwroot/js` 配下を確認し、対応する `.ts` を持たない不要な生成物が存在しないことを確認(手動で発見した出所不明の残存 `wwwroot/js/BlockTypes.js` は削除済み)。
- 未解決事項: なし。Babylon.js導入時(ステップ3以降)に必要な型定義の追加方針は導入時点で設計書へ追記する。
